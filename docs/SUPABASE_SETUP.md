# Подключение Supabase

## Когда подключать

Подключай базу после того, как главный сценарий работает локально.

Supabase нужен, если записи должны:

- переживать смену устройства;
- быть видны владельцу или команде;
- иметь вход и права;
- использоваться реальными людьми одновременно.

Для лендинга без формы, статьи или локального калькулятора база может не понадобиться.

## Учебный быстрый путь

1. Создай отдельный учебный проект Supabase.
2. Открой SQL Editor.
3. Примени `supabase/migrations/001_airc_records.sql`.
4. Создай пользователя владельца.
5. Скопируй UUID пользователя.
6. Выполни:

```sql
insert into public.airc_members (workspace_id, user_id, role)
values ('airc-demo', 'UUID_ПОЛЬЗОВАТЕЛЯ', 'owner');
```

7. Открой `runtime-config.js`.
8. Поставь `dataMode: "supabase"`.
9. Заполни Project URL и publishable key.

Publishable key предназначен для браузера и работает вместе с RLS. Он отправляется в заголовке `apikey`, но не как `Authorization: Bearer`: Bearer-заголовок содержит только access JWT после входа пользователя. Supabase secret key и legacy `service_role` в браузер вставлять нельзя.

## Проверка

1. Отправь публичную форму.
2. Открой внутренний экран.
3. Войди владельцем.
4. Убедись, что запись появилась.
5. Измени статус.
6. Обнови страницу.
7. Выйди и проверь, что список закрыт.

## Как сохраняется контакт после квиза

Анонимный пользователь может создать результат, но не может читать или менять эту строку. Поэтому в Supabase-режиме необязательный контакт сохраняется отдельной публичной записью `lead` с категорией результата. Владелец видит обе записи после входа. Так starter не выдаёт анонимному посетителю SELECT-доступ к общей таблице.

## Ограничение starter-а

Публичная вставка защищена проверками базы, но не имеет server-side rate limit. Для реального запуска добавь серверную точку приёма, ограничение частоты и антиспам.
